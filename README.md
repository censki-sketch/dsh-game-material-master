> 已通过本地模拟接口、真实 ffmpeg、React 浏览器与原模块回归检查；真实 API 的动作、方向、轮廓和帧间一致性仍须验收，预览版不保证每次生成都可直接用于游戏。

**从一张角色设定图出发，批量做出游戏里真正要用的素材。**

图片结果的「流转到」可以把当前原图或抠图版本送到八方向、序列帧、俯视地图或45°地图，支持选择已有或新建项目。目标列表排除已归档、已隐藏和已移除文件夹中的项目。送到八方向时可明确选择填入「角色细节参考图」或「八方向外观图（四列两行）」，只替换所选位置；后台仍为旧版时会阻止八方向图流转并提示完全退出 DSH（包括托盘）后重启，避免误替换角色图。目标拥有独立副本；地图先确认素材尺寸、占格与通行属性，再加入素材列表，流转本身不调用生成服务。

图片输入区的参考图使用方形缩略图，灰色编号覆盖在图片底部，悬停或聚焦显示移除图标。动作、角色图与八方向图卡片未选择时加号与灰色文字整体居中，选择后文字覆盖在预览底部。项目素材中的历史参考图按实际使用轮次展示，并标明「参考图」；同一图片用于多轮时，各轮保留对应引用。

模型在主输入栏选择，优化提示词弹窗不再重复显示模型信息或预留说明区域。

动作选齐后，本地 ffmpeg 自动合成完整 4 秒、四列两行的八方向白模参考视频，不调用生成模型、不保存输入草稿，也无需先上传角色图或填写提示词。动作卡片右侧的「参考视频」在合成中显示加载状态，完成后显示缩略图，点击即可预览。空态图标和灰色文字与动作卡片对齐。弹窗支持播放、暂停、拖动进度和循环；未更改动作时重复打开复用预览，动作、分段或背景色变化后自动更新。八方向外观参考图应按四列两行排布，支持 1536×1024 等图片比例，原图直接保留，无需改成视频比例；本地参考视频与视频输出仍按固定画幅处理。实际提交使用同一套白模渲染逻辑；服务商可能对参考视频输入计费。

结果只有原图时不显示「原始结果」标签，有抠图版本时保留版本选择。

白模八方向和序列帧使用聊天布局，一次发送保留一轮，视频、原始帧、抠图、合成与重绘作为本轮版本切换。生成模式上传角色图和四列两行外观图，各必传一张；「解析视频」只上传视频，无需选择动作或确认分段，默认解析整段视频。上传与动作选择使用同排方形卡片：图片和视频直接显示缩略预览，所选动作循环播放本地预览，替换和清除按钮在悬停或聚焦时出现。执行方式、动作数量、优化及模型切换保留在下方单行工具栏，发送按钮固定。生成新视频必须填写本轮提示词，空白或纯空格时发送按钮与快捷键不可用，后台也会拒绝；解析已有视频无需提示词。「优化提示词」沿用 DSH 模型，打开不请求，采用只更新草稿。模板选择、内容查看、统一模板管理和最终提示词预览收在优化弹窗内；图片和视频按类型管理，旧模板自动保留。抽帧、抠像和合图通过顶部「处理配置」调整，默认开启，也可在历史轮次单独执行。模板和处理参数随轮次保存，高清重绘仍需另行确认计费。**更新后需完全退出 DSH（包括托盘）再重开。**

白模抽帧保留视频的原有分辨率细节再切分八格，768P 不再先降至 480P；单格内容最多 432×480，再置于 512×512 画布。抠图从实际视频格内采样背景并修复混色边缘，避免人工纯色边框使偏色背景残留。原视频和原始帧保留，透明 PNG 与素材包另存为本轮版本。480P 视频缺失的细节仍需可选高清重绘补充，放大画布不会提高原生清晰度。

结果上方显示时间与轻量「执行详情」，画面下方使用同一条结果工具栏：操作按钮在左，版本、预览方式、动作和方向选择器在右，方向放在最后；八方向预览隐藏方向，行走试玩同时隐藏动作与方向，按内容宽度排列；空间不足时分行，操作按钮保持单排。下载合并为一个菜单，区分当前帧、视频抽帧素材包和 AI 高清素材包；旧包未记录来源时保留中性名称。视频抽帧及本地抠图不会记为 AI 清晰化。「AI清晰化」分开选择重绘方案与处理范围：默认处理当前动作、当前方向，可选 4 帧一张（2×2）或 8 帧一张（4×2），也可逐帧重绘。处理范围为当前动作当前方向、当前动作八方向或手动选帧；紧凑选择器按方案、每方向帧数、范围排列，方案和帧数控件分别为 104px 和 88px，窄屏自适应；手动模式改为同排的动作和方向筛选。「8 帧一张」每方向仅选 8、16、24 帧，四帧拼图和逐帧方案可选 4、8、12、16、20、24 帧；切换八帧方案时向上调整到可用档位。各方向在整个动作范围均匀取样，少于所选数量时使用已有帧，保留原动作时长。手动选帧支持动作、方向筛选，跨筛选保留勾选，也可选择或清除当前可见帧。取消 24 帧下限，后台计算实际调用数与帧数，确认费用后才执行；已完成帧默认跳过。本次所选帧全部完成后，自动按该范围合图与高清 ZIP 导出，保留原动作时长和源帧索引；失败不混入未重绘帧。原视频默认按 24 FPS 提取，2 秒动作每方向有 48 个源帧；清晰化选帧数单独控制。手动选帧也按所选方案合并请求；后台未返回同一方案时阻止提交，提示完全退出 DSH（含托盘）后重启。按钮悬浮提示跟随浅深色主题。

新任务默认按 **24 FPS** 计算抽帧：两秒动作每方向 48 帧，旧轮次保留原帧数和时长。处理配置可设 1–60 FPS，单段最多 720 帧；这属于采样，不是 AI 插帧。结果直接自动播放，可切动作和方向、八方向同时预览或 WASD 试玩，素材包单独下载。图集按 4096×4096 上限自动分页，`animation.json` v2 记录每页帧范围与方向。高清重绘使用固定修复规则及动作帧、角色图和对应方向外观参考，4 帧一张请求 2048×2048、8 帧一张请求 4096×2048、逐帧请求 1024×1024；均拆分或规范为 512×512 透明帧。分组减少请求次数，费用仍取决于服务商的尺寸与计价；模型也可能改变布局或动作，需检查质量与帧间一致性。

视频中的动作切换可能晚于预设时间。「单独执行」支持原视频定位预览、选择动作和设置起止点，可跳过过渡动作后重新抽帧；帧数按实际范围重算，原视频和旧版本保留。

动作选择支持中英文搜索，说明收在标题感叹号内；可切换单方向或八方向同步预览，共用播放、暂停和重播。上传与动作卡片整排靠左，缩略图和动画在卡片内居中铺满，名称叠在底部；滚动条仅在滚动时显示，停止后隐藏。预览读取内置素材，不调用生成模型。

图片与视频共用的优化弹窗将模板选择、管理和「提示词预览」集中在上方，原文与结果编辑框对齐。预览默认收起，在同一区域切换模板内容和最终提示词，参考图对应关系单独排列；右上角使用关闭图标。弹窗及标题采用一致的不透明主题底色，避免底层文字透出；模板保存按钮与下拉共享同一背景，未修改时显示中性颜色。本次布局调整只需刷新插件页面。

审核模式位于输入工具栏首位；视频生成与提示词优化模型在同一个分组菜单中切换，并同时显示当前型号。视频选择仅影响当前任务，费用确认显示实际型号和分辨率，轮次保存提交快照。解析已有视频无需动作素材或动作选择，默认整段抽帧，起止时间与抽帧数量可在处理配置调整；人工模式在抽帧后暂停合成。

火山方舟 **Seedream** 负责生图，**MiniMax**（或本机 **ComfyUI**）负责图生视频，抠像、抽帧、
像素量化、合图全部在本机用 `ffmpeg` 完成——不需要任何系统图像库；AI 生成步骤会把参考素材发送到你配置的服务。

> **白模流程上手**：按上方 GitHub 命令安装 → 重启 DSH → 侧栏点「游戏素材大师」→
> 配置 MiniMax-H3-Lite 视频接口及可选高清重绘接口 → 新建白模任务 → 导入角色和八方向图 → 手动选择两个动作；已有视频可直接上传解析。
> 原有转圈截帧 / 逐方向生图仍可通过「原有八方向流程」进入。
>
> 侧栏使用**游戏手柄图标**，入口上还有一个**小折角菜单按钮**：点它直接弹出八个功能，一步跳进要用的那个；
> 不用的功能可以在设置里关掉（见「功能管理」）。

工作台顶部的**侧栏开关**可以像 Codex 一样收起项目 / 任务列表，让内容区占满宽度；窄屏时它会变成抽屉，
支持点击遮罩或按 Esc 关闭，并会记住你上次的选择。

图片模块左侧统一显示「项目」，标题旁的箭头只收起列表，顶栏面板图标收起整个侧栏，两种状态分别记忆。
图片、音乐、音效复用同一套项目侧栏：置顶、归档与撤回、未读、重命名、右键菜单、手动排序和折叠保持一致，各模块分别记住选择与排序。音乐和音效也使用聊天时间线，描述与结果按轮保存，输入框固定在底部；参数和素材按需打开，日志收在每轮的执行详情里。
没有项目时，侧栏显示居中的图标与空状态。音乐、音效的配置错误显示在输入框上方的独立提示卡片中。音频下拉按钮完整显示文字与箭头；窄屏时，音乐输入框左侧选项可横向滚动，审核与发送按钮保持在右侧。
音效输入框的加号用于上传参考素材，悬停或键盘聚焦可查看参考限制与计费说明，不再单独显示感叹号。
顶部「打开文件夹」直接使用系统选择窗口，读取该目录内已有的图片项目，不创建项目或生成图片。文件夹旁的新建图标优先返回该文件夹尚未生成的编辑草稿，不会反复创建空项目；切换聊天或刷新后，未保存的文字、模板选择和参数可继续恢复，参考图保留。草稿生成或明确导入结果后，再次新建才开始下一个项目；点击「生成」才把项目列到该文件夹下，后续生成保留在同一项目的历史中。明确导入已有图片作为结果也会保留为项目。参考图上传与编辑不会新增列表项。
文件夹始终使用打开／关闭图标表示折叠状态，悬停时保持图标不变。分组紧凑排列，悬停整行使用灰色背景；图片项目只显示一行名称，数量保留在带聊天图标的悬浮信息卡里。文件夹详情不显示更新时间，单个图片项目详情仍保留时间。数量包含当前和历史版本，同一版本不重复计算，新抠图版本独立计数。
文件夹更多菜单按「置顶、编辑、在资源管理器中打开、归档聊天、移除项目」排列，配合细线图标与分隔线。再次点击更多、点击外部或按 Esc 都可关闭。新建仍使用文件夹旁的独立图标。置顶文件夹单独显示在「项目」上方的「置顶」分组，没有置顶时隐藏；两个分组可独立展开收起并记住状态，标题无色块背景、间距紧凑。归档仅将该文件夹当前可见的图片项目收入本机归档列表，提示提供「查看」「撤销」；侧栏底部始终显示「已归档聊天（数量）」入口，数量为0也可点击查看空状态，进入后可取消归档或返回，也保留「整理项目 → 查看归档聊天」。图片和历史保留。
单个图片项目行悬停或键盘聚焦时显示「置顶」「归档」两个快捷图标，替代原来的更多菜单；图标使用统一细线样式，悬停提示为黑底白字的圆角浮层。文件夹和分类菜单保留。单独置顶的项目显示在「置顶」分组，两种布局都支持，与置顶文件夹同时存在时不会重复。归档只处理该项目，提示支持查看和撤销；归档页使用紧凑的项目列表，提供「取消归档」「彻底删除」，不显示置顶。恢复后保留原置顶状态；彻底删除须在弹窗中确认，弹窗显示项目名和实际目录，确认后永久删除该项目目录及其参考图、结果与全部历史，保留父文件夹和其他项目。空列表在侧栏剩余区域居中显示，不显示空文件夹。
右键图片项目行（或聚焦后按 Shift+F10）可重命名、置顶／取消置顶、标记未读／已读、归档、永久删除，也可复制名称、项目 ID 或实际目录。菜单操作绑定右键目标，不切换当前聊天；重命名使用弹窗，永久删除仍须二次确认。未读状态在本机记忆，圆点位于行末，悬停或键盘聚焦显示快捷图标时暂时隐藏，打开该项目后清除。归档中的右键菜单提供取消归档，不显示置顶。
文件夹信息卡的「编辑项目」及菜单的「编辑」打开名称与源文件夹弹窗，可为本机分组命名、添加或移除关联目录；文件保持原位，新项目使用第一个源文件夹。编辑弹窗左下角可「移除本地项目」；文件夹菜单的「移除项目」须二次确认。这些移除操作仅隐藏本机侧栏入口，保留全部图片和历史；重新打开原文件夹可恢复项目。置顶、归档和本机显示设置会在刷新后保留。
整理图标使用两级菜单，可按保存目录分组或合并显示；合并时仍保留独立的置顶文件夹，其余项目合并为列表。选择最近更新／手动排序；手动模式可拖动整个文件夹或单个项目，也可聚焦后按 Alt + ↑／↓ 调整顺序，刷新后保留。文件夹分别在置顶区、普通区内排序。

图片页面使用聊天时间线：每轮描述、参考图、执行状态和结果放在一起，输入框固定在底部。完成状态统一显示在本轮执行状态中，结果图不再重复显示完成标签。已收藏使用实心书签和蓝色底框。右侧定位条支持预览、跳转、当前轮次高亮和收藏；窄屏使用轮次目录。参数、抠图和项目素材共用按需打开的面板，日志默认折叠在对应轮次内。

原图和每个抠图版本可分别收藏，图片下方和素材卡同步显示空心／实心书签，状态在本机按项目保存。素材卡标明参考图、原始结果或抠图版本，以及所属轮次与张数。移除重复的整轮收藏，右侧定位条根据该轮是否有已收藏图片高亮，时间移到每轮底部操作栏。版本使用跟随浅深色主题的自定义下拉菜单，选中项显示勾选，已收藏版本显示蓝色书签，支持键盘、Esc及点击外部关闭；自动抠图也可切回原图。只有一张图片时隐藏缩略图条。图片顶部不再显示重复菜单或「设为当前结果」；底部循环箭头用于重新生成当前图片，「复用提示词」直接回填描述，更多菜单中的「复用本轮」回填描述、参考图与参数。最终请求弹窗使用右上角 × 关闭。这些调整只需刷新插件页面。

这些本地操作不调用生成接口。旧项目无需迁移。此更新包含宿主代码，请完全退出 DSH（包括托盘）后重新打开。

八个模块共用同一套「生成 → 验收 → 重跑」工作台。每个阶段都能**单独重做**，每份产物都能
**逐项打「通过」**；「审核模式」可以选 agent 自动审完就往下走，也可以选每一步停下来等你点头。

> 💡 **模块⑤「45°地图编辑器」的几何由代码保证，内容由你导入。**

## ① 八方向图生成

八方向与序列帧工作台统一使用项目侧栏、顶部阶段导航和居中内容区。侧栏与图片生成共用样式和行组件，支持分组收起、排序、置顶、未读及归档/撤回。高级参数与日志默认收起，上传区和空状态更紧凑；新建项目使用主题弹窗。切换阶段保留编辑内容，原有生成、费用确认、抽帧、抠像、审核与导出流程不变。本次界面调整刷新插件页面即可查看。

新增默认入口 **「白模动作流程」**：角色与八方向外观图 → 选择 2 种动作（最多 3 种，实验性）→ 本地拼接 4 秒白模参考 → 编辑提示词 → 一次生成 480P 八方向多动作视频 → 确认实际分段并抽帧 → 可选逐帧高清重绘 → 按动作导出 PNG / 图集 / 时长 JSON。全程可在 DSH 操作，提示词支持模板、手动编辑或可选本地 / 第三方文字模型。

内置 [Hormelz](https://hormelz.itch.io/8-directional-melee-character) 的 40 种 CC0 动作。视频和重绘真实计费，提交前显示数量与可编辑估算；裁切和导出免费。480P 放大不能还原原生细节，AI 重绘的动作与帧间一致性仍需验收。配置、恢复与限制见 [白模动作流程](docs/MOTION_WORKFLOW.md)。以下原有流程仍可通过「原有八方向流程」进入。

一张正面设定图进去，八个方位一次做完：**绿幕图 → 行走视频 → 序列帧 → 精灵整图 → 可操控预览**。

```mermaid
flowchart LR
  S(["设定图"]) --> I["① 八方向绿幕图"] --> V["② 行走视频"] --> F["③ 提取序列帧"] --> P["④ 合成整图"] --> W(["⑤ WASD 预览"])
```

### ① 的两种生成方式：转圈截帧（默认）/ 逐方向生图

八张方向图有两条产法，产物完全一样（`images/<方位>.png`），所以后面四步不用换做法：

| | **转圈截帧（默认）** | 逐方向生图（备选） |
|---|---|---|
| 做法 | 先生成**一段**「角色原地匀速转一整圈」的绿幕视频，再按时间轴截出八个方向的帧 | 八个方位各自生图，按依赖顺序 |
| 花费 | 一次视频调用 | 八次生图调用 |
| 一致性 | **八个方向同源**：同一个角色、同一段光线、同一套画风 | 模型每次都要重新理解角色，脸型/发色/服装容易漂移 |
| 调位置 | 时间轴上有**八个可拖动的圆圈**，拖到哪一帧就切哪一帧（本机重切，免费、即时） | 逐张重新生成 |

界面上那一排圆圈就是八个方位的截帧位置，底下的缩略条带是整圈候选帧——对着画面拖，
松手就重切那一张（并自动作废这个方位的行走视频与序列帧，避免新旧朝向混在一起）。
默认位置是「从正面开始、匀速转满一圈」的等分假设；模型实际转的方向或快慢不一样时，
直接拖圆圈，或点一下「转圈方向」重排。改变候选帧数（8~512）会自动重抽，并把拖过的位置按比例换算。

### 也可以直接用**自己电脑上的视频**（阶段①、②都能）

两处「要生成视频」的地方都不只有「调模型生成」一条路：手上已经有一段合适的视频时，
点**选择本地视频**把它选进来即可，产物和生成出来的完全一样，后面几步照旧走。

- **阶段①·转圈视频**：选进来的是「角色原地匀速转一圈」的绿幕视频，导入后插件会**立刻**
  自动抽候选帧并切出八个方向，接着拖圆圈调位置就行。
- **阶段②·某个方位的行走视频**：每一格都能单独选自己的一段（固定机位、原地走），
  之后照旧在第 3 步「提取全部序列帧」。
- 支持 MP4 / MOV / M4V / WebM / MKV / AVI（按**文件头**认，不看扩展名），单个 ≤100MB；
  这一段只在本机用 ffmpeg 处理，不会上传到任何模型。
- 换掉某一段视频时，它下游已经抽出来的帧与整图会自动作废，避免拿上一段视频的帧去合成。

### 中间图片都能存下来

一路生成下来的**每一张图**都能保存：八方向绿幕图、转圈候选帧与整圈条带、每段视频抽出来的
绿幕帧与手动选帧候选、抠完绿幕的帧、合成整图。界面里看得见的产物每张都有「保存」链接；
候选帧一抽就是 32~64 张，所以底部另有一个 **保存全部图片（zip）**——打成一个包，里面按项目
目录的结构摆好（`images/…`、`turn/…`、`frames/…`、`keyed/…`、`out/sheet.png`）。
生成出来的成片（转圈视频、八段行走视频）同样各自有一个「保存视频」链接。

### 怎么用

1. **新建项目 → 上传设定图**，写提示词（转圈截帧用的是**一份转圈视频提示词**；逐方向生图是每个方位一份，
   另有「统一附加提示词」八个方向共用）。
2. **生成转圈视频**（默认路径）：角色原地匀速转一整圈，绿幕背景。视频到手后插件会自动抽候选帧
   并切出八个方向，一般不需要你动手。**逐方向生图**（备选）则是**一键生成全部**：八个方位按依赖顺序
   出绿幕全身图。逐张能看到用时、落到哪个模型；不满意就**重新生成**这一张，或展开**编辑提示词**只改它。
3. **生成全部视频**：让角色在原方位原地走三步。这一步最贵、也最慢（单段 1~6 分钟）。
4. **提取全部序列帧**：每段视频按时长平均抽帧，这里同时完成统一裁剪、缩放与**像素风量化**。
5. **合成整图**：剔除绿幕，按行序拼成一张精灵图；行序可用 ↑↓ 拖动调整，合成前可存参数。
6. **行走预览**：用 WASD 或方向键操控角色，八方向接得顺不顺，一眼就能看出来。

## ② 图片生成

按提示词出图，可选参考图。开启提示词框内的**透明背景**后，自动补充纯色背景要求，生成后按同一底色本地抠成透明 PNG，无需单独设置抠像参数——也可以直接上传一张已有图片，
只走抠像不花生图的钱。静态图片会在本地恢复发丝和背景夹缝中混色边缘的颜色与透明度，无需额外安装模型或依赖。已有图片可手动重新抠像，无需再次生成。「按当前参数重新抠像」会先保存当前抠像参数，持续显示处理状态直至后台完成，再更新主图、缩略图与 PNG 下载链接，避免继续显示或下载旧缓存。

静态抠像也会保守修复封闭小区域中的混色残留，颜色无法确定时保留主体。残留处可点击当前透明结果 →「局部补抠」：进入时保留当前缩放，滚轮放大后单击残留颜色，只清除所选半径内颜色相近的连通区域，范围与颜色容差使用主题下拉菜单，直接按住鼠标拖动查看，拖动不会触发补抠，支持撤销和取消。点击「保存新版本」后需在弹窗中再次确认，取消确认保留补抠预览；原图与旧版透明图保留在历史中。预览、补抠和保存均在本地完成，不消耗生图额度；历史和参考图预览只读。

透明背景提示词会要求底色作为独立图层、不参与主体照明或反射，未指定光照时采用中性白光，阴影沿用主体固有色系；优化提示词、最终请求预览与生图共用这些规则。提示词只能降低背景染色风险：如果原图已将底色画进头发或物品内部，重新抠像无法可靠还原其原色，也不能自动去掉所有紫色或绿色，否则会误伤本来需要的颜色。

点击顶部或输入区的参数按钮打开设置面板，模型以只读信息展示，尺寸与张数集中排列；抠像参数分为「背景识别」「边缘处理」，背景色、预设及色值保持同排，较长说明可点标题旁的提示图标查看。面板中可以切换生成参数、抠图设置和项目素材。输入框的「+」可添加参考图或导入已有图片，导入与抠像均在本地完成。

### 怎么用

1. 在底部输入框写主提示词；需要共同要求时，在**优化提示词**中选择或管理基础提示词模板。
2. 可选：拖入参考图，或点击「+ → 添加参考图」（最多 10 张）。附件在输入框上方横排显示缩略图与 `@图片N` 编号，点击可预览原图；主提示词和优化弹窗都可输入 `@` 选择并高亮引用。
   有效的 `@图片N` 引用按 Backspace / Delete 整块删除。需要透明 PNG 时打开「透明背景」；抠像参数和已有图片操作在设置面板中。
   基础提示词选择器、查看内容与管理入口仍在「优化提示词」弹窗原提示词输入框底部，保持同一行。模板内容可查看，切换只更新草稿，关闭再打开保留选择。
   模板管理的说明收在标题旁的感叹号中，右上角新增模板，标题与下方内容保持紧凑间距；编辑区右侧使用「保存模板」分体按钮，下拉菜单提供放弃修改、恢复内置内容或删除自定义模板。删除仍需确认，内置模板不可删除。
3. 从输入区的参数按钮设置尺寸与张数，再点击底部的圆形**上箭头**生成；审核模式使用同排的紧凑文字下拉。发送后立即显示描述，服务确认提交后清空已发送文字，保留继续输入的新草稿。生成期间上箭头变为停止方块；停止只中断本地等待，已提交的服务请求仍可能计费，不自动重试。生成前先保存最新描述和参数，保存失败时不会提交。
4. 每次生成追加一轮消息，旧结果保留在时间线上；一轮多图使用左右箭头或底部缩略图切换。点击主图放大预览，背景占比与张数显示在图片上方。执行详情和日志默认折叠；下载位于图片下方，移除图片顶部重复菜单和旧的「通过」「设为当前结果」入口。底部循环箭头用于重新生成当前图片，成功或失败轮次均按该轮请求快照只提交一张，保留当前输入草稿；仅无快照的旧失败记录使用当前输入。失败原因集中在执行详情，网关 HTML 错误不再展示源码。

添加、审核模式、生成参数、透明背景、优化提示词、模型选择与生成按钮统一位于输入框底部同一排，窄屏可横向滚动。不再显示「@ 参考图片」按钮，仍可在文字中输入 `@` 选择参考图。审核下拉箭头固定居中，展开与收起时原地旋转。各功能的保存、上传、操作失败等反馈统一以浮层消息弹窗显示；成功自动收起，错误可手动关闭，不再占用页面横条。

主输入栏同时显示当前生图模型和提示词模型，切换后立即更新名称。模型菜单按「生图」「提示词」分组，点击模型名称直接切换，不另开弹窗。生图列出火山方舟、ToAPIs 和自定义后端已配置的模型，缺少必要配置时禁用对应项；切换影响全局。DSH 提示词模型按项目记住，沿用已有登录与用量规则，不修改 DSH 默认模型。进入聊天与打开菜单只读取模型信息，不提供重新读取或测试按钮；读取与切换均不调用生成接口。设置按服务管理连接，自定义服务支持多个连接及每个连接多个模型；默认打开当前使用的连接，输入栏移除重复的尺寸设置按钮。

优化弹窗保留可编辑原文、结果、基础模板选择与最终请求查看，去掉重复模型选择、参考图提示行和只读标签；说明放在标题感叹号里。原文与结果仍支持高亮 `@图片` 引用。空聊天的欢迎内容居中，项目素材为空时显示图标、说明与添加参考图入口。主输入栏的优化按钮使用透明背景和彩色图标；所有底部操作始终同排，空间不足时可横向滚动。

生成结果与本地抠图、局部补抠版本保存同一个轮次 ID，在同一条消息内切换版本；旧记录通过来源关系兼容归并。切换聊天后再切换窗口或重新打开插件会保留当前聊天、草稿和阅读位置，已经处理过的旧回链不再覆盖选择。

提示词优化适用于角色、道具、武器、建筑和场景，先区分目标、必须修改、明确保留与参考用途，再整理主提示词；不自行增加美术设计。选择「不使用模板」时不会额外注入角色模板。优化弹窗在同一次模型请求中返回「需求核对」；目标不明确时显示需要补充的问题，禁止采用空结果，补充原文后再手动优化。需求核对是模型理解供人工检查，不保证实际生图一定符合要求。

优化和生图使用相同参考范围：主提示词或附加提示词中有 `@图片N` 时只发送指定图片，否则发送全部已上传参考图，原编号与附图顺序的对应关系包含在最终请求中。透明背景开关和准确底色一并发送给优化器，背景规则不锁定主体修改。仅在优化提示词弹窗中展开「查看最终生图请求」（未优化时预览原文，优化后预览结果），免费查看当前草稿拼接模板、参考图对应关系及背景要求后的完整提示词；不会调用模型，实际生成以点击生成时的最新设置为准。更新后需完全退出 DSH（包括托盘）再打开。

透明区域在结果图和放大预览中均以棋盘格显示，参考图预览也采用相同背景。

点击当前结果、历史图片或参考图打开预览后，可用鼠标滚轮缩放，放大后按住鼠标拖动查看细节。图片底部工具栏居中排列为「原始大小 / 缩小、比例、放大 / 适应窗口」；说明图标位于标题「预览」右边、图片名称左边，关闭按钮在右上角。打开预览不会自动展开说明，悬停、点击或键盘聚焦说明图标时才显示。双击图片恢复适应窗口，关闭后再次打开会重新适应窗口，所有缩放操作均在本地完成，不修改原图、不调用模型。

时间线按时间从旧到新展示每一轮，包含提交时的描述、附件与参数快照；失败和重启中断的轮次也会保留，中断提示结果未知、可能已计费，绝不自动重试。右侧定位条悬停预览、点击跳转；收藏和阅读位置在本机按项目记忆。查看旧消息时新结果不会强制滚动，点击「有新结果」或「回到最新」可跟进。切换项目或刷新会恢复未保存输入和阅读位置。在更多菜单点击「复用本轮」并确认后，将描述、匹配的参考图和参数回填输入区；外层可直接「复用提示词」。复用不会自动生成，点击生成才提交；模型与后端沿用当前全局配置。本地抠图作为原轮次的图片版本保留，可切换查看。

历史不自动清理。可手动删除历史记录；仍被当前结果或其他历史使用的图片文件会保留。删除整个任务会同时删除其历史。旧任务现存图片会显示为「旧版记录」，没有当时参数时不能复用；升级前已被覆盖或删除的图片无法恢复。更新后需完全退出 DSH（包括托盘）再打开。

主提示词与优化弹窗的参考菜单仅在光标紧挨着 `@` 时弹出，继续输入文字后收起。优化器不再将参考图中可见的服装、发饰等逐项扩写为必须保留的清单，先描述修改完成后的主体。静态图片抠像沿与背景连通的偏色边缘恢复前景颜色与透明度，覆盖细发丝和深入轮廓的背景夹缝，并保护稳定的主体色块及被干净前景隔开的紫色细节；视频流程不变。单张图无法完全区分真实同色细节与背景污染，原图已画入的宽色边仍需检查。更新后需完全退出 DSH（包括托盘）再打开，并手动对已有图片重新抠像。

## ③ 序列帧生成

比八方向图更「一次到位」的路径：给一张首帧图（或参考图 + 参考视频），直接生成一段循环动作，
再抽帧、抠像、横向合成并**原地循环播放预览**。

```mermaid
flowchart LR
  A(["首尾帧 / 参考图 + 参考视频"]) --> V["生成视频"] --> F["提取序列帧"] --> K["抠绿幕 + 横向合成"] --> L(["循环播放验收"])
```

### 怎么用

1. 选模式——平台规定两种互斥：
   - **首尾帧模式**：一张图作为起始画面（尾帧可选）；
   - **多模态参考模式**：参考图 + 参考视频，用来约束风格与动作。
2. 写提示词、选模型 / 时长（4~15 秒）/ 分辨率，点**生成视频**。
3. **提取序列帧**：抽帧、统一裁剪、像素量化。
4. **绿幕抠像与合成**：调好抠像参数后合成横向条图；右侧预览区会按帧率循环播放，
   **动作连不连贯、抠像边缘稳不稳，直接看播放**。
5. **验收**：三步各自打「通过」。

## ⑦ 音乐生成编辑（谱乐 AI）

在底部输入一段灵感或贴一整首歌词，点击发送图标后，插件会先建音乐任务（后续轮次复用该任务），
再开一个**不挂靠任何项目**的 DSH 新对话，把任务 id、本轮 id 与用户原文一起发进去。对话里的 agent 会：

1. 先读内置的**音乐创作指南**（风格提示词结构、歌词 13 点 QC、Suno / Mureka / MiniMax / ACE-Step
   的选择、生成设置经验值、游戏循环 / 短曲 / 响度目标）；
2. 扩写/结构化提示词；用户给了完整歌词时**以歌词为权威文本**，只做断句、结构标签、发音的最小修正；
3. 按用途选引擎与模式（默认 Suno `chirp-v6`；纯音乐 / 固定 BPM 可用 ACE-Step 等），提交生成；
4. 提交后等平台返回，按需要做**本地免费**的后期（裁剪 / 音量 / 淡入淡出 / loudnorm）；
5. 把工具返回的 `openUrl` 贴成 Markdown 链接。

点开链接就回到音乐页：歌曲可试听（路由支持 Range，能拖进度）、看波形、裁剪、调音量、淡入淡出、
标准化到 -14 LUFS / -1 dBTP、保存成新版本、导出 MP3 / WAV / M4A（多产物自动打 zip）。
原曲永远保留，所有编辑结果都是新版本。生成按谱乐 AI 积分计费；插件不代收，也不会为「确认状态」重复提交。
原曲与编辑版在本轮的版本下拉中切换，可分别收藏；同时只播放一个音频。切换项目或刷新后，未发送的描述与参数仍会保留，重复点击新建会回到未提交的草稿。

### 谱曲模式（本地 MIDI，谱曲/试听免费）

新建音乐时，可在输入框底部的创作模式中选择 **「本地谱曲」**。它不直接让 AI 出音频，而是：

1. 对话里的 agent 先分析你的想法：用途、情绪弧、曲风、调性与主音、BPM、拍号、段落表、配器、主题动机；
2. **先用你的语言把方案输出给你看**，再 `saveMusicScorePlan` 落盘（manual 模式会停在这里等确认）；
3. 写一份 `compose.py`（[scoremill](https://github.com/CharlesCNorton/scoremill)，MIT 文本记谱库），
   交给插件在本机执行，产出 `score.mid`；
4. 宿主解析 MIDI，并用 **FluidSynth + SoundFont**（没装就用内置简易合成器）渲染试听；
5. 回界面逐版试听、看波形、下载 MIDI / 试听、打「通过」、导出乐谱包（MIDI + 试听 + `plan.md` + `compose.py`）；
6. 你提「太吵 / 太慢 / 鼓太多 / 第二段太长」时，agent 只改对应段落，**每次修改都是新版本**，旧版保留；
7. 满意后可以在该版本的更多菜单里点「交给 Suno」，确认计费后，插件会先把这一版的**试听音频上传**给 Suno
   作为参考（标准上传免费），再走 **cover** 生成 —— Suno 不接受 MIDI 原文件，但接受音频，所以这是
   「MIDI → 渲染音频 → 上传 → cover」的链路，比只发文字标签更贴近你的配器与段落。若 Suno 判定音频有版权，
   会提示你确认后走付费版权通道。结果仍是重新演奏，不会逐音一致。

**依赖**（设置 → 游戏素材大师 → 谱曲模式里有探测与路径输入）：

设置页默认只显示就绪状态、Python / scoremill / ffmpeg 版本和 Python 路径，「重新检测」位于标题右侧。可选的 FluidSynth / SoundFont 路径收在「高级设置」，安装说明、费用和来源说明放在标题感叹号中；各依赖旁的感叹号可查看完整路径与错误。本次界面调整刷新页面即可。

- `python3 -m pip install scoremill` —— 写 MIDI 必需；
- `fluidsynth` + 一个 `.sf2`（默认找 `~/Library/Audio/SoundFonts/FluidR3_GM.sf2`）—— 更好的试听，可选；
- `ffmpeg` —— 转 MP3 / 导出（已有音乐模块也需要它）。

谱曲、试听、导出全部在本地完成，**不消耗谱乐 AI 积分**；只有最后交给 Suno 才计费。

## ⑧ 音效生成（火山引擎 Seed-Audio）

音效这一模块不派给对话，界面上直接生成：写一句「要什么声音」，选格式与采样率，点「生成（计费）」。
格式、采样率、音调等放在右上角「生成参数」里，底部用发送图标提交。每轮保留当时的描述、参数与参考素材；失败可确认后重新生成，也可「复用本轮」回填后修改，不会自动提交。旧版记录缺少参考快照时只允许复用文字和参数。右侧可定位历史轮次，素材面板支持全部打包导出。

- **提示词当导演脚本写**：声源 + 环境 + 强度/节奏 + 大致时长。例如「暴雨中的金属撞击，短促有力，
  约 1 秒，带一点尾音」。单次输出上限 **120 秒**；接口没有 duration 参数，时长只能写进提示词。
- **参考素材（可选）**：1 张参考图（图生音）或最多 3 条参考音频（每条 ≤30 秒 / ≤10MB），两者不能同时用；
  参考音频在提示词里用 `@音频1…@音频3` 引用。
- **每次生成一条 take**：旧 take 永远保留，可以在界面里逐条试听 / 导出 / 打包；失败不会自动重试。
- **默认模型** `seed-audio-1.0`，默认输出 WAV / 24000Hz（可切 MP3 / Ogg Opus 与
  16k / 24k / 32k / 44.1k / 48k）。
- **Key 是语音控制台的 API Key**（请求头 `X-Api-Key`），**不是**火山方舟的 `ARK_API_KEY`；
  `seed-audio-1.0` 需要先在语音控制台开通。设置页的「生成测试（计费）」确认后会真实生成一条极短音效，
  会产生少量费用。
- 计费按返回的 `original_duration`；重试会再计费，失败/重试前请先确认。
- v1 不做本地剪辑（裁剪 / 淡入淡出 / 响度标准化），只做生成、试听、下载与导出。

## 用对话驱动

八个模块（含实验性的骨骼动画与全本地的 45° 地图编辑器）的**全部功能都能通过对话调用**。插件只注册**一个**工具
`game_material`：先按主题读手册，再按手册里的方法名调用。详细的流程、方法表与参数**按需加载**，
不会在无关任务里常驻上下文。

| action | 作用 |
|---|---|
| `guide` | 读手册：`overview` / `workflow` / `config` / `methods` / `ai-asset` / `map-agent` / 八个模块主题 |
| `intake` | **固定流程第 0 步**：先把关键参数与审核模式问清楚，再动手 |
| `call` | 万能通道：插件全部远程方法逐个可调（`{method, payload}`） |
| `upload` | 按本机文件路径上传素材（设定图 / 参考图 / 首尾帧 / 部件…） |
| `reviewMode` | 记下审核模式：`auto` 自动审核 / `manual` 每一步人工审核 |
| `status` | 看一眼当前进度，以及现在该做哪一步 |
| `wait` | 阻塞等到「没有任务在跑」，回来就是可审查状态 |
| `review` | 出**验收包**：每个产物的绝对 URL、状态、通过标记、深链接 |
| `approve` | 打「通过 / 取消通过」 |

例如：

```js
game_material({ action: "guide", topic: "sprite" })        // 先读八方向图手册
game_material({ action: "intake", module: "sprite" })     // 问清参数与审核模式
game_material({ action: "call", method: "runTurnVideo", payload: { projectId } })
game_material({ action: "wait", module: "sprite", id: projectId })
```

地图编辑器还支持 Agent 专用的「读状态 → 画 → 看效果图」闭环：

```js
game_material({ action: "call", method: "mapInspect", payload: { projectId, region: { r0: 0, c0: 0, r1: 16, c1: 16 } } })
game_material({ action: "call", method: "mapRender", payload: { projectId, region: { r0: 0, c0: 0, r1: 16, c1: 16 }, overlay: { markers: true, grid: true } } })
// 把返回的 localPath 交给 read_image；iso 用 isoInspect / isoRender
```

旧版按 `game_material_call` / `game_material_status` / … 逐个注册的工具已经合并到上面这一个工具，
迁移对照见 [docs/ENGINEERING.md](docs/ENGINEERING.md#对话调用agent-也能驱动整条流水线)。

验收链接是**深链接**：agent 在回复里贴出的 `openUrl` 点一下就切到插件对应页面，原地落到
对应模块 / 项目 / 阶段上，不需要你自己翻。

每个模块的项目 / 任务标题旁都有「**复制 ID**」按钮（侧栏项目行里还有 `⧉`），点一下就把
`projectId` / `jobId` 复制到剪贴板，直接粘贴给 agent 即可。

**本 Fork 请使用页首的 GitHub 版本包或源码安装命令。** 以下 npm 命令安装的是上游版本，不包含此 Fork 的白模流程。

Web 部署用 `--public-url https://host/prefix/` 时，深链接与产物地址会跟着补路径前缀。

装完**重启 DSH**（宿主半区在启动时装入）。浏览器半区按磁盘上的 `lib/client.js` 现取，
刷新浏览器即可生效。

**依赖**：`ffmpeg` / `ffprobe` 得能找到。查找顺序是 `FFMPEG_PATH` / `FFPROBE_PATH` 环境变量 →

本包**没有任何运行时 npm 依赖**，`zod`、`cordis` 等全部从 DSH 自身的安装树解析。

> 从旧版 `dsh-8dir-sprites` 升级时，首次启动会自动迁移数据目录，已有项目无缝接上。

## 配置

「本机依赖与数据」的重新读取按钮位于标题右侧。新建项目默认参数按画布与抽帧、抠像、像素与裁切分组，输入框统一对齐，背景色控件横向排列；窄面板自动减列，参数说明可从分组标题旁的感叹号查看。仅调整展示，参数范围、默认值与失焦保存方式保持一致。

「插件数据目录」显示配置、索引和默认位置项目的根目录；素材实际位置以各项目文件夹为准。此显示修正包含宿主代码，更新后须完全退出 DSH（含托盘）再打开。

**设置 → 游戏素材大师**：

设置默认打开第一个「生图」分类，使用左侧分类导航和右侧表单，隐藏顶部业务页签；标题左侧箭头返回之前的模块。高级参数与较长说明默认收起，下拉菜单统一跟随主题。

火山方舟连接页已移除仅用于骨骼部件重绘的模型输入框和对应的高级配置折叠区；各模型的高级参数仍在模型编辑弹窗中。本次仅调整界面，刷新插件页面即可。

在「生图」左侧通过「添加连接」配置自定义接口，或使用火山方舟 / ToAPIs 快捷预设。连接页只显示名称、Base URL、API 格式、API Key 和模型列表；复制、删除连接收进右上角更多菜单。地址与协议失焦或选择后保存；Key 编辑后失焦或按回车自动保存，切换连接也会保存。Key 在设置页读取后用密码框隐藏，点击眼睛查看原值；保存后保留真实输入，不用固定圆点替换。输入框右侧清除图标在悬停或键盘聚焦时显示，清空会同步移除保存的 Key；清除隐藏时眼睛靠最右侧，显示时向左让位。仅查看不会改写配置，保存失败保留输入并提示；遮罩字符不能作为 Key 保存。旧版地址、Key 和模型会自动迁移。火山方舟 / ToAPIs 预设也可从更多菜单删除：移出列表并停用生图，配置保留供重新添加，ToAPIs 视频设置不受影响。

模型由用户手动添加：填写模型 ID、显示名称并设置启用状态。每个模型独立保存尺寸、质量和超时等参数，编辑弹窗的「高级配置」默认收起，只展示当前协议支持的项目；ComfyUI 工作流也在其中，修改后点击保存。模型行提供测试、编辑、删除和独立启用开关；状态圆点区分未测试、通过与停用。生成输入栏显示自定义名称，实际请求仍发送模型 ID；同名模型显示所属连接。

连接或模型停用后从生成栏与模型目录隐藏，地址、Key 和参数保留。关闭或删除当前模型后，新的生成与测试会被拦截，需要手动启用或另选模型，不会自动切换接口。已有连接及模型保持原状态；新增连接默认关闭，模型可独立启用。添加连接、模型和修改参数均不会生成图片；测试需确认计费。ToAPIs 的图片开关不影响视频配置，图片和视频继续共享连接地址与 Key。

查看配置、读取模型列表与切换模型不会调用生成接口。「生成测试（计费）」需要再次确认；自定义连接可选择待测模型，测试结果按连接与模型记录，修改凭据、地址或协议后需要重测。MiniMax、ComfyUI 视频和音乐的「测试连接」仍只检查服务，不提交生成。**本次更新包含宿主变更，需完全退出 DSH（包括托盘）后重新打开。**

### 自定义生图后端

除了火山方舟，插件也支持把你的**自己的生图服务**接进来（设置 → 游戏素材大师 → 生图后端）：

| 协议 | 生图 | 带参考图 | 说明 |
|---|---|---|---|
| OpenAI API | `POST {base}/images/generations` | `POST {base}/images/edits`（端点不存在时退回 generations 的 `image` 字段） | 兼容 OpenAI 官方与各家兼容网关；`b64_json` / `url` 两种返回都认 |
| ComfyUI API | `POST {base}/prompt` → 轮询 `/history` → `GET /view` | 先 `POST {base}/upload/image`，把文件名写进工作流 | 需要**API 格式**的工作流 JSON；`{{image}}` 占位符没写时自动改 `LoadImage` 节点 |
| Stable Diffusion WebUI API | `POST {base}/sdapi/v1/txt2img` | `POST {base}/sdapi/v1/img2img`（`init_images` + 重绘强度） | 需要 WebUI 以 `--api` 启动；API Key 填 `user:pass` 走 HTTP Basic |

本地服务通常不需要 API Key；地址填**主机根**（例如 `http://127.0.0.1:8188`），具体端点由插件按协议拼。
配好后可选择模型，点击「生成测试（计费）」并确认，提交一张真实测试图；不会自动重试。

### 本地 ComfyUI（图生视频）

不想用 MiniMax、或想跑自己的模型时，可以把**图生视频**这一步接到本机的
[ComfyUI](https://github.com/comfyanonymous/ComfyUI)：在「设置 → 生成视频 → 本地 ComfyUI」启用，
填上地址（默认 `http://127.0.0.1:8188`），粘贴工作流 JSON 后点击「保存工作流」——API 格式、或编辑器里直接
保存的界面格式都行。Cookie、注入点和尺寸覆盖位于「高级设置」。
生图、抠像、抽帧、合图完全不受影响，与 MiniMax 走同一套下游流程。

- **两种格式都收**：`Workflow → Export (API)` 导出的 API 格式最直接；编辑器里直接保存的**界面格
  式**（顶层是 `nodes` / `links` 数组）也直接粘——插件会先转成 API 格式，那句「已自动转成 API 格
  式（N 个节点）」会出现在测试后的「连接详情」。转换会跳过便签与静音 / 旁路节点；若那份 JSON 连控件
  值都没带 `widget` 信息（很老的 ComfyUI 版本），插件会提示你改用 Save (API Format)。
- **注入点自动探测**：提示词写进哪个节点的哪个输入、首帧图从哪进、宽高 / 时长 / 种子覆盖哪几个
  输入，插件会自己认一遍，认到的结果显示在「连接详情」。认错了就在高级设置中手工填 `节点ID.输入名`
  （例如 `1.text`）覆盖。
- **首帧图**：工作流里已经有 `LoadImage` 就直接用它；没有时插件会读 ComfyUI 的节点定义，在
  「声明了 `IMAGE` 输入却没接线」的位置（例如 `FreeVideoGenerate.first`）自动补一个 `LoadImage`
  接过去。
- **内置模板就是 FreeVideo 那条链路**（`FreeVideoGenerate` + `FreeVideoMedia` + 一个空
  `LoadImage`，首帧接在 `FreeVideoGenerate.first`——与官方示例
  [FreeVideo-All-in-One.json](https://github.com/FlashML-org/FreeVideo/blob/main/example_workflows/FreeVideo-All-in-One.json)
  的接法一致）。改坏了点「更多 → 恢复内置模板」还原；官方那份界面格式的 JSON 也可以直接粘进来用。
- 产物照旧：ComfyUI 只负责吐出那段绿幕视频，**抽帧、抠像、合图仍然是本机 `ffmpeg` 干的**。
- 「测试连接」只读 ComfyUI 的版本、显卡与队列长度，**不排队、不生成、不产生费用**。
- **Cookie（可选）**：ComfyUI 自己不做鉴权；只有当它被挡在需要登录的反向代理后面（Cloudflare
  Access、Basic Auth 之类）时才用得上。从浏览器开发者工具里把 Cookie 整段复制过来即可，插件会
  先归一化成一行，再让**每个请求**都带上它 —— 上传首尾帧图、提交、查询、取回成品视频，一个都不落。
- 本地后端**不支持「多模态参考模式」**（参考图 / 参考视频）——那是 MiniMax v2 的能力，
  走 ComfyUI 请用首尾帧模式。

### 功能管理（隐藏不用的模块）

不用的模块可以在**设置 → 游戏素材大师 → 功能管理**里关掉，随时再打开，已有项目数据不会删：

默认将「图片生成」排在第一位；已有手动排序保留，点击标题右侧同排的「恢复默认顺序」可恢复。每行悬停或键盘聚焦时可点击铅笔重命名（最多32字），支持恢复默认名称；名称同步到功能栏与快捷菜单，不改变功能标识、排序、隐藏状态或已有数据。名称保存涉及宿主配置，更新后需完全退出 DSH（包括托盘）再打开。排序与隐藏说明收在标题旁的感叹号中。设置左侧依次为生图、音乐、音效、生成视频、提示词模板、画面与抠像、功能与数据。

- **界面**：工作台页签、侧栏快捷菜单里都不再出现它；如果当时正停在这个模块，会自动落到第一个可见模块。
- **对话**：`game_material` 的 `guide` / `call` / `status` / `intake` / `upload` / `wait` / `review` / `approve`
  一律拒绝，报错里说明去哪里打开。只藏界面不拦工具等于没藏——模型看不见页签，
  照样能调生成类方法真实计费，所以宿主半区每次都按最新配置再拦一次。
- 可见性**只能由用户在设置页里改**：工具面拒绝 `saveConfig({hiddenModules})`，
  否则模型能自己把隐藏的功能放出来。
- 全部关掉也是允许的，工作台会提示「所有功能都已被隐藏」。

## 界面语言

**插件界面跟随 DSH 自身的语言设置**（设置 → 通用 → 语言），中文 / 英文都是一等公民，
切换**即时生效**、不用刷新页面：工作台标题、八个模块页签、每一张卡片的按钮、提示条、
弹窗与设置页全部跟着走。

实现上不猜也不复制 DSH 的语言状态，而是接 DSH 的 `locale` 服务
（`@deepseek-ai/dsh-client-locale`）：插件把中英词条表注册进去，之后所有界面文案都从它取。
服务不在时不报错，界面退回中文原文。

**内置默认提示词也跟着切。** 八方向生图提示词、行走视频提示词、转圈视频提示词在英文界面下
就是英文版——它们会真的发给 Seedream / MiniMax，所以语言得跟界面一致，不然用户读不懂
自己在调什么。规则是「只换没改过的那些」：手改过的提示词切语言时一个字都不动，
点「重置为默认」得到的是**当前语言**的默认值。提示词存在宿主侧（宿主拿不到 locale 服务），
所以浏览器半区每次读项目、重置提示词时把当前语言一起带过去。

范围说明：**多语言覆盖的是浏览器半区的界面文案与内置默认提示词**——工作台标题、
八个模块页签、每一张卡片的按钮与提示条、弹窗、设置页、验收控件、默认提示词。
以下两类仍是中文，因为 DSH 目前只把 locale 服务提供给浏览器半区：

- **运行日志里由宿主写入的行**（「开始生成「南 · 正对镜头」」「…生成完成，用时 12.3 秒」等）
  以及拆件质检给出的动态结论；
- 对话工具返回给模型看的文本（`game_material_status` / `review` 的渲染、`intake` 的追问）。

界面上能点、能改、能验收的部分都是双语。

## 常见坑

- 提示词别用「剪影」——生图模型会照字面把角色画成纯黑轮廓。
- 区分「转身」和「视线」：写方位时要补「只绕竖轴转身、视线始终水平」，否则会变抬头仰视。
- 图生视频不保证守住纯色背景（可能被打光成渐变），所以抠像不认单一绿色。
- 重复提交会被拦截（界面与对话都拦），避免白花钱。

### 加一条界面文案

中文原文**就是**词条表的 key，所以正常写代码即可：

```ts
h("span", null, T("正在装配定位…"))                       // 纯文案
T("第 {n0} 帧", { n0: index + 1 })                        // 带插值，英文可自由换语序
```

然后在 `src/client.ts` 的词条表（`i18n-ignore-start` / `i18n-ignore-end` 之间）补一条英文；
漏了也不会崩，`verify-i18n.mjs` 会拦下来。批量包老代码用
`node scripts/i18n-wrap.mjs src/client.ts --write`（词法级、幂等，可反复跑）。

改代码后如何生效：

| 改了哪里 | 怎么生效 |
|---|---|
| `src/client.ts`（浏览器半区） | 刷新浏览器即可 |
| `src/*.ts` 宿主半区 | 重启 DSH（或 `--patch` 热重载） |

## 已知取舍

- **像素风来自后处理**（抽帧阶段的像素量化），不来自提示词——Seedream 会忽略「像素画」类指令。
- **拆件质量由生图模型决定**，是当前最大瓶颈。模型偶尔会「换角色」或把角色拆成服装裁片；
  最可靠的路径是「上传自己的部件 PNG」（文件名即部件名），完全绕开生图。
- **自动装配只对「部件就是参考图上整块肢体」的素材可靠**；真实立绘走生图拆件时，
  建议用 agent 视觉先验或手工拖放校正（这些步骤都不花钱）。
- MiniMax 偶发内容审核拒绝（实测约 10%），换一版更中性的提示词重试即可。
- **本地 ComfyUI 的耗时不可预期**：任务在本机队列里可能排很久，也可能中途显存不足失败。
  插件只负责提交与轮询，失败原因（执行到哪个节点、抛了什么异常）会原样带回界面，
  模型 / 显存层面的问题要回到 ComfyUI 自己的控制台看。
